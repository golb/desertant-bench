Desert Ant models on a MacBook Air M5

SDK desert-ant-core 4.1.0 · Apple M5 · 32 GB · macOS 26.6.2 · public data: FLEURS, AMI (CC BY 4.0)

This independent benchmark measures seven models on public data and authored synthetic controls so the results can be inspected and reproduced. Every number below comes from results/*.json; the core stages re-run with uv run python scripts/run.py all.

Speech recognition: Voz vs Whisper large-v3

100 FLEURS test sentences per language, one recording per sentence. Both models get the language code. Whisper is whisper.cpp 1.9.1, large-v3, 8 threads, Metal, default decoding, no prompt. Voz is v0.4.0 through the Swift SDK. Each model loads once per language; load time is excluded and listed below. WER uses the same normalisation for both models (case, punctuation, ё→е); numbers are left as written, which costs both models alike.

Timing in this block was measured on AC power with the CPU 83.77% idle before the stage (gate: AC and ≥85%). Accuracy numbers are unaffected; the controlled Clear stage below shows the same speed ratio range.

Control: level-normalised input

Many FLEURS recordings are very quiet (RMS around −60 dBFS). To separate level from noise, the same 100 clips were normalised to −23 dBFS RMS first, then mixed with noise, then run through Voz with and without Clear.

inputVoz WERVoz WER after Clear
clean speech5.84%6.06%
white noise, 15 dB SNR7.16%13.18%
white noise, 5 dB SNR13.18%36.25%

Clear leaves clean speech almost untouched, so the model is not broken. On broadband noise it costs the recognizer accuracy, and more so on quiet input. Clear is documented as a listening-quality model, not an ASR front end, and white noise is a synthetic stress test, not one of the rooms it is built for. My takeaway for an app: keep Clear on the playback path and feed the recognizer the original audio, unless a real-noise test says otherwise.

Findings

  1. Clear writes 48 kHz on the streaming path even when 16 kHz is requested
    enhance(path:to:options:) goes through enhanceStreaming, which uses ClearDSP.sampleRate for the writer and never reads options.sampleRate (Sources/Clear/Streaming.swift). The in-memory path resamples. Not touched by the open 4.2.0 release PR.
  2. Title can drop a negation in the description
    "Please do not publish the draft before the review" became "requires the draft to be published before the review date". Same prompt string as Titles.prompt, temperature 0, deterministic.
  3. Ear marks some Russian clips as Ukrainian with isReliable = true
    Confidence up to 0.94. Looks like the confident-confusion case the SDK already handles for Nordic languages.
  4. Clear in front of ASR raises WER on broadband noise
    Not a bug: a usage note worth a line in the docs. Clean speech is unaffected; see the control table above.

Not measured

  • p95 or SLAs: one pass per clip for ASR, three runs for WHO.
  • Energy, temperature and clocks during runs; only power source, CPU idle share, load average and macOS thermal warnings are logged.
  • Voz with vocabulary boost; Whisper with VAD or a prompt on this set.
  • Whether Clear helps on real (non-synthetic) noise; white noise is a stress test, not a room.
  • Other devices. One MacBook Air M5.
